这是范围与优先级记录，不是已承诺的交付日期。具体工作在 `codex/dev` 持续开发，按功能提交和构建，按用户要求整理阶段 PR；验收结果保留在交接记录，有阶段 PR 时汇总到 PR。

后续业务方向见 [五页产品方案](product-plan.md)、[题材研究与候选规则](theme-research-spec.md) 和 [实施计划](delivery-plan.md)。这些文档记录已确认方向和待验证建议；规划进入版本管理不表示其中的页面重构、研究算法和后端接入已经实施。

## 已实现的前端预览

- Rust + GPUI 原生应用，当前提供 Windows MSVC Release ZIP、核心独立测试与 Windows 原生状态/交互检查；使用原生控件与绘图，不嵌入网页。
- 已按 React 设计复刻行情、盯盘、涨停、题材、复盘五页前端，统一浅色/青色视觉、导航、全局搜索、个股速览和状态反馈。
- 十一类业务面板：股票列表、图表、关键数据、十档盘口、成交明细、逐笔成交、委托明细、资讯、模拟交易、订单与持仓。
- 组件可自定义名称；每个股票列表为独立分组，可添加/移除现有模拟目录中的股票，保留空列表、搜索与排序。
- 股票列表可从粘贴文本或 TXT/CSV 批量导入，自动识别、预览、去重并提示目录外代码，确认后仅追加到当前分组。
- 窗口内停靠、独立窗口、跨窗迁移、联动组、布局模板、撤销、自动保存与旧文件保护。
- 新增组件默认独立窗口，支持组件标题拖动及按目标/方向重新插入，保留当前浅色配色。
- 顶部自定义看板栏，独立组件组合、布局和浮窗；支持命名、复制、排序、删除与旧单布局迁移。
- 分时/日 K/周 K/月 K/1 分/5 分、价格与成交量均线、十字线、缩放和平移；确定性模拟行情与当前会话的模拟账户。
- A 股分时固定全天时轴、竞价参考价与实际撮合区分、午休分界、未来留白与盘后保留；股票目录共 18 只，其中 12 只 A 股，保留旧美港股样例及所属市场时段，不自动扩充用户已有列表。
- 分时单击开关十字线与左右吸附数据卡，鼠标/键盘逐分钟定位，显示对应分钟量额和累计均价；历史分时同样支持。
- 日 K 点击定位、左右吸附详情卡和键盘逐根查看；双击打开对应日的历史分时，支持前后交易日导航，分钟数据与模拟日 K 量价一致。
- 独立盯盘分组及成员管理、列数/排序、全局监控和静音状态、规则编辑、手动生成演示异动与个股跳转。
- 涨停多日板块矩阵、字段文本 AND 搜索、资料编辑、样例导入和整日删除/恢复；题材对象、四日周期、梯队、八日关键词及截止日联动证据展示。
- 复盘按日预案、多个独立草稿、仅卖出预案、盘中笔记、人工热点/手法/手工收益和独立原生阅读窗口；输入校验及按 ID 编辑。
- 显式跨页路径：资料 → 题材/个股速览 → 选择业务日引用草稿，或预览去重后加入盯盘，保留原资料日期和依据。
- 独立 `desktop.json` 保存新业务数据，防抖写入、有效旧文件备份、坏文件与外部改动保护；行情 `workspace.json`、旧 Dock 协议和布局撤销保持兼容。

## 已落地的架构边界

- Cargo workspace 分为应用、`tydaro-core` 与 `tydaro-ui`。核心规则可以脱离 GPUI 独立构建；基础组件不依赖股票业务，页面与 Gallery 共同消费。目录拆分之外，用依赖 guard 和独立 CI 检查约束方向。
- `src/app/mod.rs` 负责组成和初始化，通过 `WorkspaceHost` 注入主窗口内容与生命周期；工作区不直接导入五页外壳、Gallery 或桌面业务 Global。共享模拟账户不再依赖面板首次构造。
- 应用按 `app`、`workspace`、`panels`、`pages`、`adapters`、`gallery`、`test_support` 七个目录组织。窗口/布局、各类面板、页面编辑/绘制及图表交互使用私有子模块，统一入口收窄可见性；Session 与各视图输入资源的所有权保持不变。
- 单测归入被测试模块，桌面文件 IO 测试移到存储适配层，公共文档约束在 core 集成测试中验证；移除六个重复的应用业务测试，原生回归按功能拆分且命令行入口不变。架构 guard 递归检查整个工作区目录，覆盖相对路径和导入。该目录整理不新增 schema 迁移。
- 桌面业务聚合只公开读取，写操作统一走受校验 Command；命令失败不改变数据和 ID。研究资料由 typed 文档承载，未知扩展字段和损坏原文受到保护。
- 面板按类型拥有原生输入与图表资源；旧内容快照独立校验，坏数据在修改 live 状态之前拒绝。图表通过可注入投影接口读取当前/历史数据；当前实现仍只有模拟行情。
- AppRuntime 拥有行情和布局维护任务；桌面/布局保存各自拥有后台任务与串行写会话，旧回调与旧写入不能覆盖新版本。关闭仍执行显式最终 flush，不把尚未完成的写入当作已保存。
- `desktop.json` 从 schema 1 显式迁移到 schema 2，保存 typed 候选证据；旧 ID、日期和来源文字不改写，不伪造历史证据。行情与 Gallery 存储 schema 不变。
- 固定模拟案例贯通收盘事实、时点归属、人工确认、首板候选和下一交易日草稿。题材页有明确的演练入口，候选冻结依据；这条链验证领域边界和页面消费，不代表完整题材研究功能完成。

上述是代码和契约范围。当前集中完善 Windows 功能，core 独立测试、workspace 编译、原生状态/交互回归及 Windows 实机验收分别记录。Windows headless 不提供像素渲染，自动检查不代表画面、DPI 或输入法已经通过。工作流新增检查不等于远端 CI 已经通过，命令与回归要求见 [开发与验收](development.md)。

上述为当前代码实现范围。具体构建和交互检查以对应提交的实际报告为准；Windows 混合 DPI、中文输入法和完整原生桌面流程仍需实机验收。React 样机继续用于设计对照，浏览器存储不与原生文件互通。

## 下一阶段：研究流程与页面调整

基础视觉已通过 [原生组件实验室](component-gallery.md) 完成逐类选择；组件库与 Gallery 分开后，按确认结果逐步应用到业务页。架构迁移保持既有页面组织，不以一次全站换肤替代组件细节打磨。

1. 行情保留已有方向和组件。明确的显示、输入、状态缺陷单独修复；密度和默认比例通过实际使用记录统一调整。
2. 涨停优先验证旧版三分区组织：日期板块矩阵、选中明细、可收起的搜索结果。补齐资料日期和连续板口径，保留原始字段与来源。
3. 题材重新围绕梯队接力、涨停后表现、扩散、相对表现和负反馈设计。四板按连续四个交易日收盘涨停；系统提供证据和建议，人工确认或调整强势/主流判断。
4. 将固定模拟候选链扩展为真实研究用例：消费已核验涨停事实、时点题材归属和人工判断，再从 T 日首板生成 T+1 二板观察候选。补齐候选排除、人工调整及后续观察，保留当时依据，不依赖后来走势改写前一晚资格。
5. 盯盘优先组件组合与稳定默认布局，包含板块列表、多个独立股票表和预警流；完整停靠能力按实际需求另行扩展。
6. 先用模拟资料验证流程与数据契约。后续以独立任务消费 AlphaDeck 行情核心，同时补齐历史日历、涨停事实和题材归属等研究数据缺口。

每阶段的前置条件与验收见 [实施计划](delivery-plan.md)。新的研究指标替代旧强度算法属于明确的业务变化；旧数据迁移与旧算法对照分别安排，不能用“完全兼容旧算法”概括。

## 研究与监控尚未完成的业务

五页复刻完成的是原生前端和本地状态，不是附件 42 的全部旧应用能力。涨停导入当前加载内置样例，尚无完整旧格式文件兼容、文件指纹去重或全部日期/连板查询；题材周期、梯队、关键词、归属和月热点仍为固定样例，资料编辑不会驱动真实算法重算。盯盘通过按钮生成演示事件，尚无真实轮询、采样计算、冷却/计次或系统语音。手工收益不等于账户核算。

核心候选链接受已经核验的连板事实，不负责从原始价格推导涨停/四板；当前 `Symbol` 仍是固定样例目录，完整证券身份、历史日历、数据修订仓库和跨市场时间协议仍待实现。历史事实与指标缓存应有独立存储生命周期，不能无界写入当前 8 MiB 人工业务文档。图表投影接口只读取已可用数据，不是 AlphaDeck 网络订阅、重连或交易接口。

需要保留的旧业务语义应使用脱敏输入和人工确认输出验证；新的赚钱效应、连续板及候选口径按 [题材研究规则](theme-research-spec.md) 单独验收。不能用 UI 出现某个字段替代算法证据。真实行情和数据库迁移另行定义任务范围。
