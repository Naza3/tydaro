# 统一研究工作台设计与 GPUI 交接

本方案通过独立的 [React 预览](../design-preview/README.md) 验证五页的信息架构、浅色视觉和操作路径。目标是把现有行情终端与用户计划增加的盯盘、涨停、题材、复盘接成连贯工作流。Rust 主程序、行情模型、数据库和布局存储没有因此替换；浏览器样机也不表示已完整实现附件 42 的旧应用功能。

## 统一的部分与保留差异的部分

五页共用左侧导航、全局搜索、正文层级、按钮、表格和状态反馈。沿用白色面板、浅灰框架、青色操作和涨红跌绿，不因参考附件的暗色建议改变已确认的项目方向。数据色与选中状态分开：选择通过浅青底、边线或标记表达，收益高亮仍保留业务含义。

页面布局由任务决定，不把所有内容套进同一种仪表盘。行情需要大图表；盯盘需要多组扫描；涨停需要跨日横向对照；题材需要对象—证据—联动；复盘需要长文本与稳定的结果区。页面标题和主要动作的位置统一，重要内容获得连续空间，次要细节放在页签、速览或编辑弹层中。

| 入口 | 默认布局及其目的 |
| --- | --- |
| 行情 | 左列表、中图表、右盘口；保留自定义看板与组件管理，让单股判断拥有最大空间 |
| 盯盘 | 左分组导航与规则、中多组股票、下异动；分组可选 1/2/3 列，窄容器减少实际列数而不压扁内容 |
| 涨停 | 条件在上、多日矩阵居中、明细/搜索结果在下；每日板块保留自己的顺序，不能把垂直位置误读为同一板块 |
| 题材 | 左对象、中周期证据、右截止日联动；较窄时用「周期与证据 / 截止日联动」切换，保持左侧对象可见 |
| 复盘 | 顶部人工热点、主体当日预案与盘中记录、右侧历史；编辑按需打开，阅读时同时看到买入与卖出条件 |

「盯盘」与「行情」区分多股监控和单股研判。「看板」是行情中的布局容器，不是与业务页面并列的概念。当前样机中，盯盘分组与行情股票列表独立，改名或移除成员不会隐式修改另一页。

## 让操作顺手的设计

**看清再操作。** 列表名称和代码分层，价格/涨幅右对齐、使用等宽数字，正文与辅助信息分级。新增页面基准 14 px，主体文字通常 13–14 px，说明和代码通常 12 px；小标签、状态和图表轴另有较小字号，不把关键结论只放在小字里。页面标题 22–24 px。常规表格行高基准 34 px，紧凑模式 28 px；两行股票行保留更大高度。密度切换目前作用于新页面通用表格，并非所有控件同倍率缩放。

**减少往返与记忆。** `Ctrl/Cmd + K` 同时搜索股票和页面；研究中的股票可先打开个股速览，关闭后原筛选、选择和滚动仍在。需要深入分析时再打开行情。预案卡片同时展示触发与放弃/持仓条件，不要求为了对照来回切换买卖页签。

**保留观察位置。** 分时固定全天时轴，区分开盘竞价、09:30 开盘、11:30–13:00 午休和 14:57 收盘竞价，未来部分留白。单击开启十字线，移动定位，数据卡吸附到另一侧，减少遮挡当前点；再次单击关闭。日 K 双击进入历史分时流程。图表继续不提供诊股、画线、工具入口。

**动作和结果相邻。** 加入分组前展示新增/重复/目录外结果；保存状态在复盘和底栏常驻；错误在编辑或保存对象附近出现，不能只显示一个瞬间消失的成功提示。弹层支持键盘焦点、Tab 和 Esc；中文输入组合期间不抢占确认快捷键。模态编辑期间先完成或关闭弹窗，再使用全局搜索跳页，避免旧编辑快照覆盖跨页新增内容。少量动效遵循减少动画偏好。

**布局调整不伤害内容。** 行情新增组件先浮出，标题可拖动，显式插入菜单提供四个方向。关闭移除组件并允许撤销。复盘阅读浮窗共享当天业务内容，自己的位置和折叠只影响阅读视图。后续原生应允许图表、列表、只读预案等组合；保存中的业务编辑流程保持完整上下文，不把相互依赖的输入框任意拆散。

预览最小框架为 1080×700 CSS 像素，面向桌面，不提供手机交易布局。字号、命中区域和分栏策略还需要在真实 Windows 字体与 DPI 下验收，浏览器像素不是原生尺寸的机械映射。

## 来源和日期保持可见

五页通过显式动作交换上下文，而不是共享一个会悄悄覆盖所有页面的全局日期。

1. 在涨停中选择日期和板块，筛选结果来自内置资料，不是实时全市场涨停池。
2. 「研究题材」定位样例对象；题材页同时显示请求截止日和回退后的实际截止日，四日周期与八日证据各自有范围。
3. 「加入盯盘」选择目标分组、预览去重后追加。未知代码不生成虚构证券。
4. 「引用为预案」显示资料日期，允许选择新的复盘业务日期；经个股速览再引用，也保留原资料日期、题材和依据；只带入股票、题材和依据，创建独立草稿。用户填写自己的买卖条件，不自动追加完成结果。
5. 盘中从盯盘异动查看股票，再回到预案补记观察。价格变化和文本预案之间没有自动交易或自动判定关系。

人工热点、自动研究、股票分组是不同对象。人工热点最多保留最新 5 条；预览不会用题材结果覆盖它。手工买入收益不是账户核算数据，也不生成持仓、盈亏金额或绩效曲线。研究区的“累计次数”不是跨日去重后的独立股票数。

## 当前预览实际保存什么

| 内容 | 当前范围 |
| --- | --- |
| 复盘按日预案、多个草稿、盘中记录 | 当前浏览器 `localStorage`，包含业务日期和记录身份 |
| 人工热点、买卖手法、手工买入记录 | 同一个复盘浏览器文档 |
| 行情看板、股票列表、浮窗与布局 | 本次会话；刷新重置，不读取原生布局 |
| 盯盘分组、排序、规则、异动与静音 | 本次会话；没有后台行情服务或真实声音 |
| 涨停内置资料增删改、研究筛选与选中 | 本次会话；不写 SQLite，不同步题材样例 |
| 活动页面、显示偏好、窗口位置 | 本次会话；启动仍进入行情 |

复盘使用 `tydaro.preview.journal.v2`，修改后 700 ms 防抖保存，也可立即保存；切换日期、关闭阅读浮窗和页面隐藏时尝试提交当前内容。成功写入后才显示已保存。浏览器禁止访问存储时转为仅会话模式；写入失败时保留内存并显示错误/重试。读取到损坏或不兼容数据时保留原值、禁止直接编辑，可重试读取或明确选择仅会话体验。

这不等同于原生事务存储：没有 SQLite 迁移、磁盘备份、跨浏览器/多标签页版本冲突处理，关闭浏览器也不能保证失败数据被保存。`file://` 的存储行为因浏览器不同；同一 HTML 用不同来源打开也不保证共享内容。样机应只用于演示，不作为正式复盘档案。

复盘校验已经用于交互：板块必填，至少一侧手法和触发条件完整，允许只写卖出计划；已填任一侧字段就需补齐该侧必要字段。不完整内容留草稿。买卖手法独立，删除选项不改历史文本。买入简介先取最近 10 笔再按收益排序；严格 `>10%` 高亮，同名人工热点按全量手工记录派生高亮。这里的浏览器实现仍不能替代旧数据库兼容与原生保存失败回归。

## 样机的业务边界

涨停页的导入按钮添加一个内置样例日，编辑和整日删除只更新这页内存；不是文件选择、SHA-256 去重、旧格式兼容解析或数据库事务。搜索支持字段文本的 AND 交集和取消条件，未完成附件中的日期范围、连续涨停、同日板块联动等全部查询语义。

题材页的四板对象、梯队、归属和关键词匹配是固定研究样例，日期控件筛选对象并展示样例截止日。涨停页导入/编辑/删除不触发题材重算；截止日变化也不代表执行了真实的联动算法。两页用于检验操作和解释方式，不作为算法对齐证据。

盯盘的走势、月热点和异动为样例；演示按钮根据当前启用规则生成一条演示事件，暂停阻止新增，静音只改变界面状态。没有真实行情轮询、15 秒采样计算、有效性检查、冷却/每日计次、声音队列或 Windows SAPI。附件中的完整规则及月热点统计需在原生阶段独立对齐，不能按 UI 文案反推已经具备业务实现。

预览拥有独立的 **12 只 A 股**目录，Rust 仍保持既有 8 只。行情关键摘要、盘口、图表分别使用演示数据，未校准量额聚合。历史分时只展示日 K 双击链路，不对应所选蜡烛的 OHLC、量额。预览按看板共享选股和图表周期；原生每组件周期、联动组和身份约束保持有效。行情附加列表只展示自己的成员快照，完整管理集中在主列表。

浏览器浮窗是同页面元素，支持标题拖动和 CSS `resize`。四向插入只拆分主图区域，没有系统置顶、完整 DockArea、任意目标命中、标签合并、跨显示器坐标或原生焦点迁移。新研究页面使用稳定的任务布局，没有任意面板停靠。复盘阅读浮窗不是独立系统进程或原生窗口。

## GPUI 复刻映射

| 预览部分 | 原生对应与边界 |
| --- | --- |
| 统一外壳、导航、按钮、表格状态 | 在 `workspace.rs` 周边抽取通用样式与页面注册；使用 GPUI Flex、尺寸约束和已有控件，不嵌入 WebView |
| 看板和自由布局 | 继续使用 `board_bar.rs`、`boards.rs`、DockArea；`transfer.rs` 保留迁移意图和窗口重建协议 |
| 股票列表、盘口与成交 | 延续 `contents.rs`；大数据表格虚拟化，数字和列宽显式对齐 |
| 股票、组件与联动 | `model.rs` 继续保存持久 ID、`custom_name`、每组件周期和联动组；新增分组模型不合并用户旧列表 |
| 图表、左右数据卡 | `chart.rs` 使用 Canvas/PathBuilder 绘图、普通 GPUI 元素承载卡片；保留现有命中和 A 股全天时间映射 |
| 历史分时 | `history.rs` 与 `market.rs` 保留冻结快照、按所选日一致聚合的原生实现 |
| 研究与复盘新页 | 建议新增 `replay`、`theme`、`journal` 业务模块及页面；当前 Rust 尚未存在这些完整能力，UI 不直接写 SQL 或计算关键词 |
| 跨页动作 | 新增携带来源/日期/股票的应用命令；写入草稿和追加分组显式处理，读取跳转保留原视图状态 |
| 复盘保存及多窗口 | 新建应用级文档服务、revision 和写入队列，视图单独保存滚动/折叠；不照搬 `localStorage` 整体快照为正式格式 |
| 盯盘监控与声音 | 新建应用级监控/规则服务及行情、时钟、声音适配器，切页或关闭阅读窗不停止监控；不能把 React 演示按钮当实现 |
| 文件导入与存储 | 股票文本继续由 `stock_import.rs` 有界处理；涨停旧格式另建兼容解析与黄金样本；`storage.rs` 的现有布局版本不因新业务被替换 |

共享业务状态不意味着跨原生窗口共享 InputState、FocusHandle 或布局实体。窗口独立创建输入与焦点，由应用命令更新同一文档；保存按文档 ID 与 revision，不按当时可见日期写入。

## 后续复刻顺序与验收

1. 固定这版五页任务结构与通用视觉。在现有 GPUI 应用上验证中文长文本、表格、焦点、窄窗口和 DPI，整理样式参数；复用已锁定工具链和布局基础。
2. 先复刻外壳、行情列表与图表视觉。保留现有竞价、午休、十字线、历史聚合、组件关闭/撤销/插入及持久化回归，不用网页样例替换原生数据逻辑。
3. 准备脱敏旧数据和黄金输出，实现涨停资料兼容、查询及编辑，再实现题材算法。累计次数、板数优先级和月热点入口差异单列验收；不作为 UI 重构顺手改算法。
4. 实现复盘领域文档、输入校验、版本化保存、失败保护及共享阅读窗。对多日期草稿、仅卖出计划、10% 边界、多个窗口编辑和迁移做行为验证。
5. 实现盯盘分组、全局监控、数据陈旧状态、预警窗口、计次/冷却与声音；接真实只读行情前保持模拟标识。跨页复制/引用使用同一应用层命令。
6. 验收完整任务链以及 Windows 100%、125%、150%、200% 和混合 DPI 多屏，补中文 IME、窗口拖动/关闭/恢复、离线、休眠和保存失败场景。Linux 继续构建与回归。

预览启动、锁文件安装、生产构建、离线 HTML 交付与 CI 入口见 [预览 README](../design-preview/README.md)。浏览器检查报告位于 `design-preview/artifacts/`，以实际运行输出为准；截图、React 交互检查、Rust 构建和 Windows 原生人工验收分别记录，不互相替代。

## 本轮验证（2026-10-16）

- `npm run build` 通过：TypeScript、生产资源和独立离线 HTML 均生成。
- React 开发模式 13 个浏览器场景、生产模式 14 个场景通过，各输出 19 张交互截图，无页面异常。覆盖既有行情、五页切换、分组追加去重、监控状态、历史来源引用、模态编辑保护、草稿校验、阅读窗共享及刷新恢复。
- 检查 1536×960、1280×800、1920×1080 的行情坐标；新页面检查 1536×960 和 1280×800，无页面级横向溢出。页面内容各自滚动，保留完整表格和预案。
- 云环境 Chromium 的 `file://` 被管理员策略阻止；本地对同一单文件使用 HTTP 验证，额外资源请求为 0。GitHub Actions 使用自己的 Chromium 再实测本地文件打开，结果见其独立报告。
- 本轮没有修改 Rust、工具链或原生布局协议，因此没有重跑 Rust 编译或 Windows 原生验收。GPUI 复刻仍是后续阶段。
