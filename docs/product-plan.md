# 五页研究工作台产品方案

Tydaro 将 `qmt-trader-studio` 中的行情、盯盘、涨停研究和复盘能力精简为一个原生研究工作台。核心流程是：从涨停资料发现题材，通过梯队与后续价格表现判断题材强弱，再结合个人买卖点模式形成次日预案，在盘中观察和盘后复核。未来行情输入使用 AlphaDeck 的后端行情核心。

本方案记录 2026-10-16 确定的产品方向。当前已实现能力仍以 [架构](architecture.md) 和 [原生实现说明](native-design.md) 为准；本文的布局和新增业务属于后续设计。指标定义见 [题材研究与候选规则](theme-research-spec.md)，任务拆分、数据接口和验收见 [实施计划](delivery-plan.md)。

## 已确认方向与待验证选择

| 范围 | 已确认的方向 | 本方案的建议或待验证项 |
| --- | --- | --- |
| 行情 | 大方向正确，组件基本完善，主要剩细节 | 保留结构；明确缺陷优先修，体验偏好通过使用记录确定 |
| 盯盘 | 现有页面问题较多，需要考虑板块列表、预警、股票列表的组合 | 推荐组件化、稳定默认布局；卡片作为可选概览，任意停靠后续验证 |
| 涨停 | 以旧程序 `limit.png` 为重要参照，重新评估布局 | 推荐恢复矩阵、明细、搜索结果三分区，并支持收起搜索区 |
| 题材 | 完全重新设计；从涨停资料发现四板股及题材，以赚钱效应辅助认定强势和主流 | 指标、观察窗口、建议标签规则需要样本校准 |
| 四板口径 | 连续四个交易日收盘涨停 | 与断板后的“N 天四板”分别存储、分别展示 |
| 题材认定 | 系统展示指标并提出建议，由用户确认或调整 | 人工结论保留日期、依据和版本 |
| 复盘 | 结合主流题材和个人买卖点，形成次日预案；允许按模式筛候选 | 首个模式采用“强势题材二板”，先筛当日首板，再观察次日条件 |
| 项目关系 | 精简重构 qmt-trader-studio；未来消费 AlphaDeck 行情核心 | 复用业务经验和数据契约，不整体搬入旧前端或默认继承旧算法 |

“强势题材二板”是已给出的模式例子，不意味着所有模式都限定为首板进二板，也不意味着所有预案只能来自主流题材。模式分别声明允许的题材范围和条件。

## 每日工作流程

```mermaid
flowchart LR
    A[涨停资料与历史行情] --> B[涨停页核查事实]
    B --> C[题材页查看梯队与赚钱效应]
    C --> D[人工确认强势或主流题材]
    D --> E[复盘页按模式筛选次日候选]
    E --> F[填写触发与放弃条件并确认预案]
    F --> G[次日盯盘与预警]
    G --> H[行情页检查个股]
    H --> I[记录观察与盘后复核]
    I --> E
```

- **盘后准备**：核对当日涨停资料完整度；回看历史涨停队列已经发生的后续表现；确认题材判断；生成下一交易日候选和预案。
- **盘前复核**：查看预案所依据的日期、题材判断和候选，补充新信息；修改生成新版本，保留原先依据。
- **盘中观察**：在盯盘中并看多个题材、候选和预警；按需打开行情；记录条件满足、失效或仍待观察。盘中判断标明截止时刻，不覆盖盘后结论。
- **盘后反馈**：查看候选为何入选、条件是否满足、后来走势如何；保留失败和放弃案例。调整模式时创建新版本，使旧预案仍可解释。

跨页携带股票身份、题材身份、资料日期、观察截止时刻、证据版本和来源记录。资料日期、预案生成日期、预案适用日期分别保存，不使用一个全局日期悄悄覆盖所有页面。

## 行情页的处理策略

行情继续承担个股价格、盘口、成交与图表检查，保留现有看板、组件和浮窗能力。先收集具体问题，再按影响安排修复。

| 问题类别 | 安排 | 问题记录至少包含 |
| --- | --- | --- |
| 数据显示错误、误操作、状态丢失、输入或焦点异常、主要信息被遮挡 | 发现后单独修复，不等待长期使用 | 复现步骤、预期与实际结果、窗口/DPI、影响对象 |
| 已明确的高频阻碍，如反复查找同一操作、频繁无效切页 | 短期使用验证后集中改一批 | 具体任务、发生频率、额外步骤、改善目标 |
| 字号、间距、工具栏位置、默认比例等偏好 | 记录若干完整使用场景后统一调整 | 使用时长、屏幕条件、任务及可对比方案 |

建议先记录 5–10 次完整使用会话；这是收集反馈的起点，不是必须等待的期限。本轮没有提供具体行情缺陷，因此不预设修复项。后续每项修改应保留已有布局、面板身份和图表状态兼容。

## 盯盘页的组件组合建议

推荐以“板块列表、股票列表、预警流”为主体，提供稳定的默认组合。卡片仅作为少量分组的概览方式；随着股票和分组增多，主要工作区使用可调整大小的表格区域。

组件化与任意停靠分两步：先分离组件职责、选择和数据联动，并允许调整分栏；实际使用证明需要多套排列或独立窗口后，再接入完整布局协议。这样可以先验证盯盘任务，不必同时重做原生窗口系统。

```text
顶部：观察日期/截止时刻、数据状态、监控状态、当前预案
┌────────────┬──────────────────┬──────────────────┐
│ 板块/题材列表 │ 股票列表实例 A       │ 股票列表实例 B       │
│ 自建分组     │ 独立来源/筛选/排序    │ 独立来源/筛选/排序    │
│ 预案候选入口 │ 支持固定某题材        │ 支持并排对照          │
├────────────┴──────────────────┴──────────────────┤
│ 预警流：时间、股票、规则、触发值、来源预案、已读/失效状态 │
└─────────────────────────────────────────────────┘
个股详情：按需速览或打开行情
```

| 组件 | 职责与关键行为 |
| --- | --- |
| 板块列表 | 切换题材、供应商板块、自建分组和预案候选；区分集合来源，不按同名自动合并 |
| 股票列表实例 | 各自绑定一个集合；独立排序、筛选、滚动和固定；至少能同时比较两个集合 |
| 预警流 | 按规则与股票记录事件，保留全部关联题材/预案；点击可定位股票与触发依据 |
| 个股速览 | 查看图表和关键字段；返回时恢复原列表选择与位置 |
| 规则设置 | 按需打开；编辑监控范围、条件、冷却与通知偏好；实际后台预警实现另有数据任务 |

列表实例可绑定“跟随选择的集合”或“固定集合”。切换左侧题材只更新跟随实例，不覆盖固定对照。股票联动只改变选股，不改变集合成员。题材动态成员、人工分组和已冻结的预案候选具有不同更新规则；预案候选更新须显式比较新增/移除后应用。

切换页面、隐藏组件或关闭一个列表视图不会自动停止全局监控。真正暂停监控须使用明确动作。重复股票的同一规则事件合并展示，同时保留关联上下文；不同规则的事件保留各自依据。冷却和去重键的细节在预警任务中确定。

窄窗口保留板块导航、一个主股票表及可打开的预警区域，其他固定列表通过页签访问。标准与紧凑密度分别调整行结构和留白，关键代码、涨幅和预警状态不能靠缩小字号勉强塞入。

## 涨停页的三分区建议

旧版 `limit.png` 的组织方式更适合“跨日浏览、看当前板块、对照搜索结果”的任务。这个判断针对信息组织：旧页面也存在右侧空白占位、搜索区偏窄、删除入口较显眼等问题，需要一起调整。

当前原生版把搜索结果与板块明细放在同一区域的不同页签，并为页标题和矩阵保留较大空间，适合展示少量样例。目标布局让三个研究区域能在宽窗口同时可见。

```text
紧凑工具栏：数据范围、日期完整度、导入/更新、搜索条件
┌───────────────────────────┬──────────────────┐
│ 日期—板块矩阵                │ 搜索条件与命中结果   │
│ 日期固定，各日板块按来源顺序    │ AND 条件、命中数     │
├───────────────────────────┤ 点击定位原日期/板块  │
│ 当前日期/板块的涨停明细        │ 可收起、可调宽度      │
│ 连板、代码、名称、原因、来源     │                    │
└───────────────────────────┴──────────────────┘
```

具体规则：

1. 保留左上矩阵、左下明细、右侧搜索命中，左右和上下分割可调整。搜索关闭时左侧使用释放的宽度；窄窗口通过切换结果视图保持可读。
2. 矩阵按日保留来源板块顺序，同行是一天；纵向同一位置不代表同一题材。真正的题材跨日趋势在题材页按稳定题材 ID 对齐。
3. 搜索条件及命中结果保持稳定。点击结果只定位矩阵与明细，不清空查询；所有区域基于同一结果集合表达命中。
4. 明细同时显示原始连板文本与规范化连续板数。缺失或冲突显示待核验，不能把“10 天 2 板”解析成连续十板。
5. 原始资料板块与研究题材分别显示；一个资料板块可关联多个题材，人工确认的映射保留来源和生效时间。
6. 在明细或结果中支持研究题材、个股速览、追加盯盘、引用复盘。引用保留原记录，重复导入不得静默复制为新的涨停事实。
7. 导入/删除属于数据管理动作，保留预览、确认与恢复路径；导入后的研究结果标记是否需要重新计算，历史预案引用不随之被覆盖。

目标验收采用数十个交易日、多板块、长原因文本和多条件命中的模拟资料。用户提供的根目录 `limit.png` 仅作为本地参考，本方案用结构图记录其布局，不将该图片作为开发依赖或提交素材。

## 题材页的重新设计

题材页围绕“哪些题材值得持续关注，证据是什么”组织。四板股是重要发现线索，人工建立的题材、三板接力和首板扩散也可进入观察；“主流”不能由单只四板股直接推导。

建议布局为左侧题材列表，中间证据工作区，右侧判断与动作区：

- 题材列表显示观察/强势/主流等人工结论、适用日期和数据完整度，可比较多个题材。
- 证据区提供梯队与持续性、涨停后表现、扩散与相对强度、负反馈四类视图。每个数值能展开样本，查看分子、分母及缺失原因。
- 判断区并列展示系统建议、支持证据、反向证据、人工结论与理由；允许暂不认定。选择“证据不足”不等于弱势。
- 确认后可把题材送入复盘模式筛选，或明确追加到盯盘。查看历史日期时，显示当时结论与后来修订的区别。

“强势”强调某段时期的相对表现和正反馈；“主流”还需要持续的梯队接力、参与广度与相对市场影响。它们作为两个判断维度保存，既保留短期强势的新题材，也允许记录“仍属主流但当日转弱”。算法口径见 [题材研究与候选规则](theme-research-spec.md)。

## 复盘页的目标

复盘以次日预案为主体。人工热点、历史记录和方法词库作为辅助信息；现有手工收益记录继续独立，不用它代替题材赚钱效应或模式效果评估。

默认顺序为“选择适用交易日 → 引用已确认题材 → 选择模式 → 查看候选与排除原因 → 填写触发/放弃及退出条件 → 确认预案”。保留独立草稿、仅卖出预案、按 ID 编辑、阅读窗口和本地保存保护。

首个示例模式：

| 时点 | 行为 | 结果 |
| --- | --- | --- |
| T 日收盘后 | 选择 T 日已确认强势的题材，筛该题材 T 日收盘首板股票 | 下一交易日的二板机会候选池 |
| 预案编辑 | 查看入选与排除原因，补充买点触发、放弃条件和观察要求 | 草稿或经确认的预案 |
| T+1 盘中 | 观察约定条件，记录未触发、满足、失效或放弃 | 预案观察记录 |
| 盘后 | 对照原始预案、当时证据和实际走势 | 用于修订模式的案例 |

候选池不自动升级为完整预案，次日二板结果不能参与前一晚筛选。股票即使次日涨停，也要分别核对用户定义的买点条件和可参与条件。具体“竞价、回封、量能”等触发规则由后续模式定义，本方案不代替用户选择。

## 视觉与交互的统一边界

保留浅色、青绿色和原生桌面方向。行情与盯盘优先数据扫描密度；涨停优先横向与跨日对照；题材优先证据及样本；复盘优先条件阅读与编辑。共用数字排版、语义色、工具栏、键盘焦点及状态反馈，不强求相同卡片外形或相同分栏。

工作流和布局先用模拟资料验证，再细化字号、间距和组件装饰。需要保留的底线是：切页不丢上下文，返回可继续操作，失败状态能被看见，长期布局与业务记录可以恢复。具体交付门槛见 [实施计划](delivery-plan.md)。
