# 原生基础组件实验室

组件实验室使用 Rust + GPUI，放在现有前端的「组件库」入口中。它用于先确定按钮、输入、选择、数据行等基础元素的结构与交互，再决定五页工作台的整体风格。当前是可操作的设计候选，尚未替换业务页面的控件。

## 查看方式

正常启动 Tydaro 后，点击左侧底部的「组件库」。也可以直接启动独立的原生实验室窗口：

```powershell
cargo run --locked --bin tydaro -- --gallery
```

该独立入口使用模拟状态，不加载或保存个人工作区。需要先准备仓库固定的 Rust 1.96.0、Windows MSVC 与 SDK，见 [构建说明](build.md)。

左侧选择组件类别，右侧默认并排显示 A/B/C。点击「仅 A / B / C」可放大单个方案，点击「三案并看」返回对照。每类可以选择一项倾向，允许撤回或清除；每次选择立即保存，重新打开会恢复。右上角「复制选择结果」可把十类结果复制为文本，用于交付设计决定。保存失败会显示错误，内存中的选择仍可复制。

## 已选组件方向（2026-10-16）

用户完成十类选择后，从仍在运行的原生 Gallery 侧栏读到以下结果。它们是后续基础组件的设计基准，不表示已经将样式应用到业务页面。

| 组件 | 选择 | 保留的结构与交互 |
| --- | --- | --- |
| 按钮与动作 | C | 操作贴近当前对象，执行后原位回执，可撤销 |
| 文本输入 | C | 默认显示内容，点击编辑，明确保存与取消 |
| 单项选择 | B | 选项行带说明，当前选择清晰可见 |
| 开关与勾选 | A | 设置行右侧开关，状态位置固定 |
| 数值输入 | B | 减少 / 增加步进器，当前数值突出 |
| 页签导航 | B | 封闭分段框，明确同组切换关系 |
| 状态与筛选标签 | B | 轮廓标签，区分只读与可选状态 |
| 列表与数据行 | B | 双行信息，主次分明，以边线表示选中 |
| 折叠与详情 | A | 标题行原位展开，保留上下文 |
| 操作反馈 | B | 完成回执与撤销入口 |

组合方向为：以 B 的信息层次与阅读空间为主，编辑和动作采用 C 的按需交互，开关与折叠采用 A 的直接操作。后续先把这十个已选方案组合在一个原生预览中，统一字号、间距、边界、圆角、焦点与反馈，再决定整体页面风格；不能因选择了某个局部样例就推定整页布局或最终配色也已批准。

## 三种方案的设计约束

三案使用同一套中性背景、青绿色操作色和涨红跌绿的语义色。同一类使用相同的示例内容和初始值，改变的是布局、信息暴露方式、点击区域、编辑时机和反馈位置。

- **A 精密工具**：紧凑、对齐、动作直接可见，适合高频操作和密集扫描。
- **B 轻量工作面**：主次分明，解释靠近对象，适合逐项阅读和设置。
- **C 情境交互**：先显示当前内容，需要操作时展开编辑或检视，适合减少常驻控件。

这些是可混合选择的候选，不要求全局只能采用其中一列。

| 基础类别 | A | B | C |
| --- | --- | --- | --- |
| 按钮与动作 | 紧凑工具条、并置动作与禁用态 | 主按钮、辅助操作与说明 | 命令执行后原位结果、撤销 |
| 文本输入 | 上置标签、描边、临近校验 | 同行属性、底线输入、紧凑反馈 | 阅读态进入编辑、保存与取消 |
| 单项选择 | 常驻分段轨道 | 带解释的选项行 | 当前值摘要、展开选择、选后收起 |
| 开关与勾选 | 开关设置行 | 勾选框与说明 | 按压式状态片 |
| 数值输入 | 数字与单位字段、范围校验 | 减少 / 增加步进器 | 预设刻度选择加精确输入 |
| 页签导航 | 底线标签 | 封闭分段框 | 纵向导航与计数 |
| 状态与筛选标签 | 状态点与独立筛选 | 轮廓标签与选择状态 | 可移除条件与恢复 |
| 列表与数据行 | 密集列对齐 | 双行主次信息与选中边线 | 简洁目录与选中项检视 |
| 折叠与详情 | 标题行原位展开 | 保留参数的摘要条展开 | 独立检查区、显式关闭 |
| 操作反馈 | 原位失败提示与重试 | 完成回执与撤销 | 原生确认对话框、取消与确认 |

数值预设是可点击刻度，不伪装成已支持拖拽的滑杆。筛选条件会改变演示结果；单选模式会改变预览行的密度；反馈重置只影响本列的三条模拟记录。输入使用原生 `InputState`，名称与阈值有真实校验，保存和取消分别操作已保存值与草稿。

## 模块与状态边界

- `src/ui_foundation.rs`：语义颜色、候选方案、组件类别与公共按钮 / 容器 / 文字包装。
- `src/gallery_controls.rs`：按钮、文本和数值样例。
- `src/gallery_selection.rs`：单选、开关、导航和标签样例。
- `src/gallery_display.rs`：列表、详情和反馈样例。
- `src/component_gallery.rs`：分类导航、三栏比较、单案查看与选择结果复制。
- `src/gallery_preferences.rs`：独立的选择文档、自动保存、恢复及失败保护。
- `src/gallery_smoke.rs`：使用生产原生元素派发真实输入 / 点击的回归入口。

组件继续复用 GPUI Kit 的输入、焦点、按钮和对话框机制。每个方案实例拥有自己的输入实体和状态；切换类别或退出 Gallery 后再返回，当前主窗口中的实体继续保留。新窗口必须新建实体，不跨窗口共享焦点或输入订阅。

Gallery 首次打开时创建实体，后续保留样例状态；使用 `Desktop` 的临时展示状态，没有向 `PageId` 添加持久化值。进入时遵守现有业务编辑门禁；回到行情使用原来的 Dock 实体。样例不调用业务状态更新或模拟账户操作。Gallery 本身不迁移业务文档；本轮架构调整的 `desktop.json` schema 1→2 兼容读取、冻结研究依据和后台保存规则见 [架构](architecture.md)。行情布局和 Gallery 偏好格式保持兼容。

十类倾向单独保存到数据目录下的 `gallery-preferences.json`（schema `1`），遵循 `TYDARO_DATA_DIR`。键使用组件的稳定名称，不依赖侧栏顺序。旧版没有此文件时从未选状态开始；旧版已关闭进程的内存选择无法自动恢复。损坏、未知版本或外部修改的原文件不会被自动覆盖；成功写入前保留上次有效文件为 `.bak`。独立 `--gallery` 入口只持久保存这些设计选择，不读取业务布局；自动回归使用内存模式或独立临时目录。

## 验证

```powershell
cargo fmt --all -- --check
cargo clippy --locked --all-targets --features test-support -- -D warnings
cargo test --locked --all-targets --features test-support
cargo run --locked --features test-support --bin tydaro -- --gallery-smoke-test artifacts/gallery.png
cargo run --locked --features test-support --bin tydaro -- --smoke-test artifacts/tydaro.png
```

Gallery 检查覆盖十类三方案的原生布局、真实输入与点击、保存 / 取消、重试 / 撤销 / 确认、隐藏输入框的焦点释放、切换类别后的状态保留、倾向选择，以及 1536×960 / 1280×800 两种逻辑窗口尺寸；也检查进入 Gallery 后返回行情时原 Dock 身份与内容不变。

锁定版本 GPUI 的 Windows 后端没有 `PlatformHeadlessRenderer`。Windows 上的 Gallery smoke 运行布局与事件断言并明确报告跳过离屏截图；视觉效果需另用实际桌面窗口检查。在提供离屏渲染器的 Linux/macOS 上，该入口同时输出二十张分类对照图和一张单案图。现有完整 `--smoke-test` 依赖离屏截图，应在对应支持平台执行，不能将 Windows 事件回归写成完整渲染回归通过。

截图和编译结果不能代替 Windows 多屏 DPI、中文输入法候选窗和长时间使用的人工验收。具体执行结果以当前交接记录为准。先逐类确认方案或提出组合要求，再把认可的基础样式逐步应用到业务页面。
