# 研究工作台实施与验收计划

实施目标是把涨停事实、题材判断、模式候选、次日预案和盘中观察连接起来，并保留现有行情工作区。产品布局见 [产品方案](product-plan.md)，统计与模式定义见 [题材研究规则](theme-research-spec.md)。基础样式改由 [GPUI 组件实验室](component-gallery.md) 验证，十类组件的选择已经记录；React 重设计已撤回。下列业务页面重构与真实数据任务仍待方案定型。

## 分阶段任务

任务沿用 `codex/dev`，每项交付明确结果和验证，不按页面外观一次性重写全部功能。先用确定性模拟资料完成闭环，真实数据接入作为独立任务；模拟资料也遵守未来数据契约和时间边界。

| 阶段 | 可交付结果 | 前置依赖 | 验收门槛 |
| --- | --- | --- | --- |
| P0 口径与任务样本 | 五页职责、布局草图、人工题材案例、首个模式收盘规则、历史样本清单 | 用户确认产品方案及已描述的收盘候选资格 | 能手工演示从涨停资料到次日预案；盘中条件可先填人工文本，不阻塞资料和指标工作 |
| P1 涨停事实与页面 | 三分区布局、统一 AND 结果集、来源追溯；可回放的涨停事实和日期完整度 | P0；先提供模拟交易日历和资料 | 矩阵/明细/搜索可同时使用；定位不丢筛选；漏日、重复、冲突字段可解释 |
| P2 题材证据与判断 | 梯队、固定队列后续表现、广度/相对表现/负反馈；人工确认与版本 | P1；历史题材归属和对应行情样本 | 指标可展开人工复算；未来数据隔离；样本缺失正确；未配置建议规则不臆测标签 |
| P3 模式候选与复盘 | 首板进二板候选规则、候选解释、预案草稿、确认与观察记录 | P2；已确认的模式字段 | T 日只筛 T+1 候选；跨题材去重不丢来源；只卖出预案和旧草稿兼容 |
| P4 盯盘组件布局 | 板块导航、独立股票表、预警流和预案入口；标准/紧凑显示 | P0 可先做布局样例；完整闭环依赖 P3 | 至少两个集合并看；固定列表不被切换覆盖；返回保留选择；模拟事件有明确来源 |
| P4b 预警规则与通知 | 采样、规则计算、去重、冷却/计次、交易时段与通知；显示覆盖缺口 | P3/P4；自动检测的触发/放弃规则已结构化；模拟源先行，真实源依赖 P5 | 页面隐藏不停止；重复/缺失不误报；重启的冷却与计次策略明确；通知可关闭且不影响事件留存 |
| P5 AlphaDeck 只读接入 | 进程接口适配、行情来源切换、查询/订阅、时效与恢复状态 | 数据契约可并行确定；真实研究还需补齐日历及历史资料 | 故障、断流、重复/乱序、源切换不污染状态；真实与模拟清楚；不连接交易 |
| P6 使用反馈与定型 | 行情细节修复、盯盘布局验证、题材规则校准、键盘与视觉收敛 | 已可完成整条任务链 | 使用记录能说明修改原因；Windows 实机检查和相关回归分别记录 |

P4 的组件与固定布局可在 P1/P2 期间并行验证；任意停靠和跨窗能力在组件身份、持久化和使用需求明确后单独扩展。P4b 的模拟时钟/事件验证与 P5 可并行。P5 的真实接入不阻塞模拟闭环，但缺失真实研究数据时，P2/P3 不能宣称已能评估真实全市场。

## 首批可直接拆出的工作项

### 涨停事实和三分区

- 以 `src/pages/limit/` 为入口，在已有私有查询、编辑和绘制模块上调整三分区布局；建立共享查询结果，避免三个区域各算一套。目录拆分本身不表示该布局和查询方案已经完成。
- 保留原始板块顺序与原文本，规范化连续板数和交易日，不把资料行数量直接当作已核验涨停数。
- 导入先预览日期、重复、冲突和缺失；确认后产生资料修订。旧文件解析和旧数据库迁移分别定义，不把现有“示例导入”改名当作完成。
- 用至少 30 个模拟交易日、多个板块和长文本检查布局；覆盖条件增删、结果定位、选中切换、窄窗口、删除恢复和跨页引用。

### 题材研究领域逻辑

- 新的计算逻辑放在独立研究领域模块，输入事实快照与截止时刻，输出指标和解释；GPUI 绘制回调只消费结果。
- 先实现交易日、四板事件和归属快照，再实现固定队列；使用人工可复算数据验证后再接入页面。
- 数据变更触发新计算版本；按请求代/修订号丢弃迟到结果，显示计算中、过期或缺数据。
- 系统建议参数不齐时显示观察证据，人工仍可判断并记录理由。参数校准完成后再启用标签建议。

### 模式与复盘

- 保留现有 `Plan`/`Draft` 的身份和校验；新增模式定义、候选快照和题材判断引用。手法词库仍可仅保存文字，不能默认转换为规则。
- 首个模式仅实现已确定的收盘候选条件；尚未结构化的次日触发/放弃条件先作为人工文本和观察项，不能声称自动检测。
- 候选重算展示与上次的差异，确认后创建新版本；原预案和候选不被数据修订覆盖。
- 复盘页面把日期、题材、模式、候选、预案放在主要路径，保留笔记、只卖出预案、独立阅读窗口和保存失败保护。

### 盯盘组件

- 提取板块导航、股票表、预警流的独立状态和事件；首先组合为可调整分栏，不直接把所有组件注册进行情 DockArea。
- 股票表绑定的集合来源明确为研究题材、供应商板块、人工分组或候选快照；绑定不改变原有行情股票列表身份。
- 共享的是行情需求和业务数据；选中、滚动、输入、焦点和订阅句柄按视图/窗口创建。
- 模拟预警先验证规则来源、事件定位、已读和监控状态；采样、冷却/计次、通知、重启恢复和历史完整性在 P4b 中验证。规则必须声明适用时段和缺失/陈旧数据处理；暂停后恢复不追补虚构的瞬时触发。

## 三个项目的职责

| 项目 | 应承担的职责 | 复用边界 |
| --- | --- | --- |
| qmt-trader-studio | 旧业务和交互的参考，提供需保留的事实语义与历史样本 | 不原样继承旧题材强度阈值、导入日连续性或全部前端功能 |
| Tydaro | 原生 UI、工作流、研究事实与判断、模式候选、预案及本地记录 | 当前模拟账户保持原范围；题材结论和个人买卖模式属于此领域 |
| AlphaDeck | 行情核心、数据查询和订阅、上游协议处理 | 通过明确契约接入，不默认提供历史涨停池、历史题材成员或完整研究结论 |

AlphaDeck 当前根 `Cargo.toml` 声明 Rust 1.98，Tydaro 固定 1.96.0。建议先通过独立进程的 HTTP/WS 契约消费行情，避免为了接入而在本任务升级工具链或引入整套前端。具体进程启动与服务生命周期在 P5 设计，不由面板直接管理。

## AlphaDeck 已有能力与研究缺口

以下是 2026-10-16 对源码和契约的核对结果，表示已有实现入口，不代表本轮做过运行验收。

| 能力 | 已有依据 | 接入约束或待补能力 |
| --- | --- | --- |
| 查询与流 | `docs/contracts/market-v2.md`；`live_service.rs` 提供 `/v2/market/query`、`/v2/market/stream`、`/v2/health` | Tydaro 需适配版本、鉴权、健康和恢复状态 |
| 报价、盘口、分时、K 线 | `docs/market-cli.md`；`market_history.rs` 定义周期、复权、日期和分页 | 按实际任务接入，不默认搬入全部 P2/P3 能力 |
| 当前涨跌停价 | `market/live_data.rs` 的 `upper_limit/lower_limit` | 当前价不等于历史每日规则、涨停池或封板事件 |
| 日期和交易时段 | `market_history/calendar.rs` 提供日期/时区/时段，同时声明 `calendar_complete:false` | 需补充完整且可核验的历史交易日历 |
| 板块目录和当前成分 | `market_overview.rs` 使用版本化目录、按选择查询成分 | 供应商板块不等于研究题材；缺历史时点归属 |
| 有限成分排行 | `market_overview.rs` 提供采样与范围信息，排行和报价非原子快照 | 不能自动视为同一时刻的完整全市场截面 |
| 字段状态和流恢复 | `market-v2.md` 的 Cell、sequence、stream_generation、baseline_complete、gap_possible | unknown/stale 不填零；重连后不假装事件历史完整 |

表中 Rust 路径相对 AlphaDeck 的 `crates/alphadeck/src/`。完整交易日、网络故障、负载和平台验证仍以 AlphaDeck 自身的 `docs/status.md` 为准。本方案不将其标为已稳定上线的后端。

真实研究依赖另外补齐：完整交易日历、历史证券状态与涨停价、按日涨停事实、历史题材成员、足够的后续价格和市场基准。首封/炸板/回封需要更细事件数据。数据可以来自后续独立的数据工程任务，不假定都由 AlphaDeck 当前版本完成。

## 最小数据消费契约

这是 Tydaro 适配层的要求，不是声称 AlphaDeck 当前协议已经原样包含全部字段。

| 类别 | 需要表达的信息 |
| --- | --- |
| 身份与能力 | 交易所与代码构成稳定证券身份；接口版本、支持市场、字段/查询/订阅能力及请求预算 |
| 来源与时间 | mock/live/replay、来源实例与代次、市场时间、接收时间、交易日、数据截止时刻 |
| 精度与质量 | 原始单位和精度、有效/缺失/陈旧/不支持、覆盖范围和修订号；未知不写成零 |
| 订阅与恢复 | 序号、流代次、基线完成状态、可能缺口；支持去重、迟到结果拒绝及明确恢复 |
| 研究引用 | 行情、日历、题材成员和涨停事实的版本；指标与候选可重放到同一 as_of |

适配层按完整请求语义与消费者归属协调共享；同一证券的不同业务、周期或参数不假定共享同一个生产者。一个面板关闭只释放自身消费者。报价分片按各自市场范围合并，单片不能替换整个列表；数据来源切换先建立新基线，旧源迟到结果不得写入新源状态。恢复遵守核心预算，终止错误不能通过自动重开订阅绕过。

AlphaDeck 的行情观察流本身会合并快照并限制事件窗口。首期真实预警按实际收到的快照判断，标明采样与缺口覆盖；逐次穿越、炸板/回封等完整事件预警需要独立的事件采集契约，不能由显示快照保证。显示刷新可合并报价，但不能额外丢掉已经收到且预警计算需要的事件。

上游账户、票据和连接由 AlphaDeck 管理。Tydaro 按后续契约使用本机服务发现和访问鉴权，不把上游凭据、临时票据或服务绝对路径写进布局、预案和版本控制。

## 持久化和兼容任务

当前 `workspace.json` schema 2 管理行情看板，`desktop.json` schema 2 管理五页业务并保存模拟候选证据，继续兼容读取旧 schema 1。本文及源码目录整理不改变这些格式或当前研究页面的固定布局事实；已有读取、备份和拒写规则见 [架构](architecture.md#桌面业务持久化)。

- 新布局若持久化，先确定所属页面、组件身份和配置文件。不要用盯盘的新布局覆盖行情 Dock 树；当前用户的股票列表与独立盯盘分组均保留。
- 新研究记录需要独立的版本化存储设计，容量应按历史规模验证；不能把全部行情、样本和历史事实无限塞进现有 8 MiB `desktop.json`。
- 新研究存储指定统一写入负责人，多个窗口通过同一业务接口修改。跨存储保存先持久化不可变证据，再保存预案引用；失败时保留旧引用和未保存的内存草稿。崩溃恢复、迁移与删除不得留下悬空引用，仍被预案引用的证据不能直接清除。
- 迁移旧预案时保留 ID、日期、手法原文、草稿、笔记和来源；缺少模式或题材判断引用时标记“历史人工记录”，不虚构引用或静默删除。
- 系统建议、人工结论、候选和预案分别保存版本。重算可替换可再生缓存，不能覆盖用户判断与已确认预案。
- 新旧格式读取、未知版本拒绝覆盖、失败保留原文件、备份、退出保护和外部修改检测都进入验收；选定 schema 后更新 architecture.md 和迁移说明再实现。
- 可回退要求：保留原文件和迁移前备份，旧二进制不得被要求读取它不认识的新 schema。回退使用兼容的数据副本，不能宣称文件原地降级无损。
