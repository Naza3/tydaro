# 架构与状态约束

当前应用是一个 Rust 二进制，使用 GPUI Kit 的原生窗口、控件及 DockArea。Windows x64 是首要交付平台；Linux 用于开发与持续验证。布局围绕可移动业务面板组织，侧边导航和应用外壳保持固定。后端、真实行情连接、CLI 和插件系统尚未实现。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `main.rs` | 程序入口与 Windows GUI 子系统声明 |
| `workspace.rs` | Session、窗口及面板注册、DockArea、联动、模板、撤销与保存调度 |
| `boards.rs` | 看板集合与顺序、活动看板、名称/身份约束与旧工作区包装 |
| `board_bar.rs` | 顶部看板栏及新建、命名、复制、排序、删除交互 |
| `model.rs` | 可序列化的面板身份、类型、股票、周期与联动组 |
| `contents.rs` | 业务面板 UI、输入状态、内容快照和共享演示账户 |
| `chart.rs` | GPUI 原生绘图、图表视口、十字线、缩放和平移 |
| `history.rs` | 源图表所属的临时历史分时窗口、固定快照和交易日导航 |
| `market.rs` | 根据股票与统一 tick 生成确定性的报价、K 线、盘口和成交 |
| `transfer.rs` | 屏幕坐标转换、拖动会话、停靠命中及迁移意图 |
| `storage.rs` | 版本化布局、输入校验、文件替换与旧文件保护 |
| `smoke.rs` | `test-support` 下的离屏渲染及真实 UI 事件回归 |

依赖方向以模型与数据为基础：workspace 组织窗口和内容，contents 使用 market 和 chart，storage 保存模型及 Dock 树，transfer 返回迁移意图后由 workspace 执行。扩展功能应放在相应模块，不在绘制回调中引入网络请求、磁盘扫描或长时间阻塞操作。

## 面板身份与窗口归属

工作区由多个命名看板组成，运行时只挂载活动看板的原生窗口和面板。切换前捕获当前看板的完整布局、内容和浮窗，目标恢复成功后才变更活动身份；失败回滚源看板。未活动看板以快照保存，不能留在 live 面板注册表中，否则股票联动和插入目标会串到其他看板。主窗口的当前位置与尺寸保持不变，各看板的浮窗按其记录重建。

看板 ID 与组件/窗口 ID 分别分配。组件与浮窗分配器扫描所有看板的历史 ID 并单调前进，复制看板会重新分配组件和非主窗口 ID，同时保留内容。看板内主窗口 ID 始终为 `0`。看板名称去除首尾空白后应唯一、非空、不含控制字符，最多 24 个字符，支持最多 16 个看板且不能删除最后一个。

`PanelModel.id` 是持久身份，GPUI `EntityId` 是运行时身份，两者不可替代。复制面板分配新的持久 ID；移动面板保留原 ID、股票、周期、表单与图表视口。主窗口 ID 为 `0`。

`PanelModel.custom_name` 是可选显示名，缺省为组件类型名称。组件标签、独立窗口标题及插入目标使用同一有效标题；组件类型和持久 ID 不因改名改变。名称去除首尾空白，空值恢复默认，最多 32 个字符且不含控制字符。旧模型缺字段时仍可读取，复制和移动保留名字，布局撤销保留存活组件的当前名字。

每个持久面板在一次完成的操作后只能属于一个窗口。跨窗口迁移先在目标窗口重建内容、输入、焦点与订阅，成功后移除源面板；失败必须撤销目标并恢复源注册。不能把绑定原窗口的 InputState 或 FocusHandle 直接挂到另一窗口。旧实体移除时不得清除已经由新实体接管的同一持久 ID。

新增和复制组件先创建独立原生窗口，再装载内容并激活焦点；创建失败要回收空窗口。新组件继承来源窗口的联动股票，复制组件则保留其快照并分配新 ID。组件类型决定初始窗口大小，窄数据组件允许缩小到 240 像素宽。

普通标签拖拽由 DockArea 处理窗口内布局，组件内部股票标题和跨窗拖柄由 DragCoordinator 处理窗口间移动。“插入面板”菜单直接选择目标面板与方向，调用同一迁移路径。源/目标锁定、失效目标或错误窗口归属必须在修改前拒绝。

拖动单组件浮窗时，命中检测跳过源窗口以便找到后面的工作区；只对持久组件总数为一的源浮窗生效，非活动标签也参与计数，不能把多标签窗口当作单组件窗口透传。原生系统标题栏仍用于移动整个窗口。

用户关闭浮动窗口会删除其中全部组件，包括未选中标签；关闭不等于返回主窗口，也不受布局锁定阻止。删除前捕获最新内容用于布局撤销，移除窗口和组件注册、取消相关拖动并保存当前看板。原生关闭回调必须校验窗口运行时身份，避免延迟事件删除已恢复的新窗口。程序性窗口回收（迁移、切换看板、恢复）保持独立路径，不解释为用户删除。主窗口关闭时先保存全部看板再退出，保留未关闭的浮窗。回归应分别验证显式删除、可撤销恢复和迁移状态连续。

屏幕命中统一在设备像素坐标中计算，再按目标显示器转换窗口位置。Windows 使用显示器 DPI；Linux X11 使用桌面坐标。Wayland 不提供所需全局坐标，禁用自由跨窗拖柄，使用不依赖全局坐标的插入菜单、弹出/返回和窗口内停靠。不要以某个 Linux 缩放配置推断 Windows 混合 DPI 已正确。

## 数据与业务状态

Session 管理统一行情 tick；各面板对同一股票和 tick 应得到一致数据。联动组 `0` 表示独立，`1` 至 `3` 的同组面板同步选股。图表周期和视口属于具体实例，不应因新开另一个图表而被覆盖。

`Watchlist` 保留序列化名称，显示为“股票列表”。每个组件的内容快照分别保存 `members` 股票成员、搜索与排序；一个组件对应一个独立分组，不使用全局自选集合。缺少 `members` 的旧快照默认采用原有六只示例股票，显式空数组必须保留为空。添加去重、移除只修改当前成员，不能因外部选股联动改变成员，也不能因移除行事件冒泡触发选股。名称和成员属于内容配置，不产生布局撤销步骤；复制内容后各组件独立修改。

`Trades` 保留原有序列化名称，显示为“成交明细”；新增 `TradeDetails`（逐笔成交）和 `OrderDetails`（市场委托明细），与模拟账户的 `Orders` 区分。逐笔数量与金额汇总回成交明细，未撤销的市场委托汇总回十档盘口。市场委托只是展示用数据，不是用户的模拟账户委托。

新增月 K、1 分和 5 分 K 线保留原有周期名称。价格/成交量均线基于完整可用历史计算后再裁剪视口；分时均价使用完整模拟交易时段，不能随着可见窗口向后滚动而重新从零累计。所有数据仍是确定性演示，市场日历和估值不代表实时信息。

图表定位以样本时间标识保存当前选中项，再映射到可见视口，不把屏幕横坐标或裁剪后的局部索引当作交易日。点击进入定位，拖动阈值把平移与双击查看区分开；切换股票或周期清除定位。定位与数据卡为临时 UI 状态，不改变原有 `ChartViewport` 存储格式。

日 K 双击发出 `ChartEvent::InspectDay`，携带股票、完整日线序列索引和当时 tick。`market::historical_session` 返回该日的 OHLC、前收、分钟数据、量额和相邻可用日；已完成日的分钟聚合严格还原同一日 K，当前日复用固定 tick 的模拟会话。均价/成交额采用相同整数分 OHLC 均值加权口径，不能引用另一天的当前报价来填历史字段。

每个 `PanelContent` 仅弱引用一个历史查看窗口，重复打开时更新并激活它。历史窗口创建独立 `MarketChart` 和焦点，冻结行情，不参与联动、布局快照及撤销；源内容释放时延迟关闭，覆盖组件移除、跨窗重建和看板切换。关闭历史窗口不修改源图，关闭主窗口仍执行原有保存退出流程。

DemoBroker 是当前进程中的共享模拟账户。提交、撤单和模拟成交更新资金/持仓及占用量，不发送真实交易。账本在重启后重置，订单输入等面板内容随布局保存。将来接入数据或券商时应建立明确的数据接口及异步边界，不能让演示按钮直接调用真实下单接口。

## 布局持久化与撤销

`workspace.json` 使用外层 `BoardSetFile` schema `2`，保存看板顺序、名称、活动 ID 和每个看板的完整 `WorkspaceFile`。单看板快照仍使用 schema `1`，包含窗口边界、Dock 树、锁定状态、面板模型与内容、ID 分配进度及暂停状态，供现有恢复/撤销逻辑复用。旧 schema `1` 文件读取后完整包装为一个“默认看板”，首次保存新格式时将原始文件保留为 `.bak`。布局保存在平台配置目录，可用 `TYDARO_DATA_DIR` 隔离测试；路径和运行方法见 [build.md](build.md)。

存储层先校验再写入，通过临时文件和替换保留旧数据。之前有效版本写入 `.bak`；不可读的旧内容保留为 `.corrupt-*`。当前不自动迁移未知 schema，也不自动加载 `.bak`；遇到不可读布局会显示状态提示并使用默认布局。修改存储逻辑时不得把备份误写为坏文件。

有效性约束包括每个看板最多 16 个窗口、128 个面板、64 层嵌套，整个文件最多 8 MiB，以及合法 ID、有限窗口尺寸和联动组。每个看板必须包含且仅包含一个主窗口，活动看板必须存在。未知面板名称及 JSON payload 在存储层保持原样；这不代表已经支持第三方插件。已知面板的坏数据应显式报错，不能当作未知类型吞掉。新增字段需定义默认值或迁移并覆盖旧数据读取测试。

委托筛选、大单筛选和盘口队列切换随内容快照保存，字段使用 serde 默认值读取旧布局。不得更名旧的 `PanelKind` / `Period` 序列化值来替换显示标题。

自动保存将活动看板的 live 快照与所有未活动看板合并写入，不能仅保存当前窗口。`template.json` 继续使用单看板 schema `1`，保存和加载模板只涉及当前看板。布局撤销历史按看板分别保留在当前会话中，切换本身不成为布局撤销项。行情时钟、暂停状态及 DemoBroker 仍全局共享，切换不倒退演示进度或账户。

应用布局前先准备目标窗口，失败尝试回滚原工作区。撤销以布局操作为主：保留仍存活面板的当前股票、周期、表单和视口，不倒退正在变化的业务状态；恢复已关闭面板时使用保存内容。ID 分配不能因撤销而倒退。现有原生窗口恢复尺寸时保留当前位置，因为当前 GPUI 没有窗口位置 setter；新建窗口及重启恢复使用经过可见区域约束的位置。

## 演进原则

优先保持上述边界与可验证行为；模块拆分应由实际复杂度推动，不预先引入通用插件系统或多服务架构。跨模块协议、布局 schema、工具链或发行方式变化时，在相应文档/PR 记录原因、兼容方案和验证证据，避免把关键决策只留在对话中。
