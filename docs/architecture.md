# 架构与状态约束

当前应用由一个 Cargo workspace 中的三个 crate 组成，最终仍交付一个 Rust 二进制，使用 GPUI Kit 的原生窗口、控件及 DockArea。当前只开发和验收 Windows x64；功能完善后再恢复跨平台，保留的 Linux 实现与构建资料暂不承担 CI 或验收要求。主窗口提供行情、盯盘、涨停、题材、复盘五个页面：行情继续使用可移动业务面板，其他页面采用各自任务布局，共用固定导航和应用外壳。全部使用 GPUI 原生元素和控件，不嵌入 React/WebView。后端、真实行情连接、面向用户的 CLI 和插件系统尚未实现。

后续的盯盘组件组合、题材指标、模式候选及 AlphaDeck 接入见 [产品方案](product-plan.md) 和 [实施计划](delivery-plan.md)。完整指标、真实数据源和页面重组仍属规划；已实现的核心边界、文档兼容读取及固定模拟候选链不代表这些产品方案已经全部实现。

## 依赖与组成边界

```text
tydaro（应用组成根、页面、运行时与适配器）
  ├── tydaro-core（业务模型、命令、确定性模拟行情与文本解析）
  └── tydaro-ui（GPUI 基础组件、语义色与交互外观）
```

`tydaro-core` 不依赖 GPUI、应用或组件 crate，不读写文件、不启动窗口或请求网络；它可以用 `cargo test --locked -p tydaro-core` 独立构建与测试。`tydaro-ui` 依赖 GPUI，但不认识股票业务、工作区、存储或 `tydaro-core`；调用者提供稳定 ElementId、原生输入实体和回调。应用同时依赖两者，承担组装与副作用。新增 SDK、数据库或真实行情协议应进入应用适配层，不能通过核心规则或基础组件反向引入。

`src/app/mod.rs` 是组成根，初始化主题、业务存储、共享模拟账户、图表数据源、Gallery 偏好和运行时，再向行情工作区注入 `WorkspaceHost`。Host 提供主窗口内容构造、主窗关闭和行情可见性查询；`workspace` 不直接依赖 `app`、业务页面或 Gallery。看板栏属于 `workspace/board_bar`，由组成根创建后交给外壳。Desktop 的 Gallery 实体按需创建；独立 Gallery 入口只初始化 UI 与设计偏好，不加载个人行情布局或业务文档。组成根不是业务规则容器，页面仍通过明确业务命令处理修改。

`scripts/check_architecture.py` 在 CI 检查核心/组件依赖方向和工作区对组成层的禁止引用。检查递归覆盖 `src/workspace/` 的生产模块，识别显式路径、相对路径与导入；测试专用模块按配置排除，并有扫描器自测。它检查 Cargo 清单与源码路径，不是完整的 Rust 静态分析器，也不能替代状态、持久化和 UI 回归。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `src/main.rs` | 程序入口、Windows GUI 子系统声明及核心类型导入 |
| `crates/tydaro-core` | 私有业务聚合与 Command、文档校验/迁移、typed 研究记录、确定性行情/证券目录和纯文本导入 |
| `crates/tydaro-ui` | 可复用的按钮、输入容器、选择、表面、文本、反馈和主题；不拥有应用数据或持久化 |
| `src/app/` | 组成根；`runtime.rs` 管理后台任务，`shell.rs` 管理五页外壳和跨页动作，`state/` 适配业务命令与保存，`ui.rs` 提供页面视觉规则 |
| `src/workspace/` | 唯一 Session、窗口/面板注册、DockArea、联动、迁移、模板和撤销；`boards/` 与 `board_bar/` 管理看板，`snapshot.rs` 定义布局快照，`persistence.rs` 调度保存 |
| `src/panels/` | 面板实例与按类型创建的控件；股票列表、报价、盘口、成交、市场委托、资讯和模拟交易各有私有模块；`broker/` 管理模拟账本，`snapshot/` 校验内容快照，`chart/` 管理绘图、交互及历史窗口 |
| `src/pages/` | `watch/`、`limit/`、`theme/`、`journal/` 四个页面入口；编辑、查询和绘制分离，私有 `research/` 只共享明确的研究样例与展示辅助函数 |
| `src/adapters/` | `desktop/` 负责业务文档 IO 与失败保护，`layout/` 负责布局文件及串行写入，`src/adapters/market_data.rs` 提供可注入图表投影和冻结历史查询；当前只有模拟行情实现 |
| `src/gallery/` | 十类组件三方案展示、样例状态及独立入口视图；`foundation.rs` 定义实验方案，`preferences/` 保存设计选择 |
| `src/test_support/` | 测试临时目录；`test-support` 下的原生工作区、五页和 Gallery 回归驱动，工作区场景按窗口、看板、列表、导入、图表和分时拆分 |

七个应用目录按职责组织，不新增 crate。各模块通过少量 `pub(crate)` 入口或重新导出供应用调用，实现子模块默认私有，协作方法使用 `pub(super)` 限定范围。`workspace/mod.rs` 仍拥有唯一的私有 Session，拆分后的窗口、布局和保存模块不各自建立注册表；外部模块不能直接修改 Session。面板、页面与阅读窗口仍各自创建输入、焦点及订阅，拆文件不改变原生实体的所有者。

短单元测试可留在实现旁，较长单测放所属模块的 `tests.rs`；原生内部断言放对应模块的 `test_support.rs`，只公开回归所需入口。业务规则测试保留在 core，重复的六个应用层业务测试已移除；公共文档约束由 `crates/tydaro-core/tests/document_contract.rs` 验证。文件 IO 测试位于 `src/adapters/desktop/tests.rs`，GPUI 业务适配状态测试留在 `src/app/state/tests.rs`。目录调整不新增持久化迁移，现有 schema、身份、字段及兼容规则保持下文约定。

工作区运行时通过注入的 Host 构造主窗口内容，Desktop 持有页面实体并继续渲染行情 DockArea；`workspace::transfer` 返回迁移意图，由工作区操作模块执行。`workspace::boards` 只依赖工作区快照类型，`adapters::layout` 依赖快照和看板模型；快照中仍保留 GPUI Dock DTO，因此属于桌面适配层，不应为了移入 core 而重造现有停靠协议。扩展功能不在绘制回调中引入网络请求、磁盘扫描或长时间阻塞操作。

`AppRuntime` 拥有行情推进和布局维护两个 Task，启动时避免重复任务，退出前停止。业务防抖保存任务由 `DesktopState` 拥有，布局保存任务由 Session 拥有；取消调度不代表已经开始的阻塞 IO 被中断，因此存储写入还需串行化和版本保护。异步文本导入继续由源视图的弱引用、请求编号及编辑版本拒绝迟到结果。未来连接重试、订阅与关闭必须明确任务所有者，不能在页面 render 中启动无归属循环。

## 页面与跨页状态

基础组件实验室是 `Desktop` 内的临时展示模式，入口位于侧栏底部，不属于持久化 `PageId`。三套方案共用语义色，通过结构、信息层级和操作方式对照；输入和样例状态存于 Gallery 实体，不操作 `DesktopState` 或行情 Dock。十类设计倾向由进程级 `GalleryPreferences` 共享，并即时保存到独立的 `gallery-preferences.json` schema `1`，按稳定组件键恢复；缺失文件从未选开始，损坏/未知版本/外部修改时拒绝覆盖并保留内存选择，可复制结果。进入时遵守业务编辑门禁；返回业务页保留原页面和 Gallery 实体。独立 `--gallery` 入口只保存设计选择，不读取个人布局。自动回归关闭个人配置读写；Gallery 自身不改变行情布局或业务格式，业务 schema 迁移另见本文后续章节，详见 [组件实验室](component-gallery.md)。

`PageId` 区分五个业务页面；切页保留页面实体以及各自的选中项、筛选、输入和滚动状态。行情内部看板继续由 BoardSet 管理，与业务页面导航分开。新研究页面不支持任意面板停靠；行情新增组件、关闭、撤销、插入和跨窗迁移仍走原有协议。

`DesktopState` 是应用级 `Global` 适配器，持有核心 crate 的私有 `Desktop` 聚合，包含活动页面、独立盯盘分组、全局监控/静音开关、规则、异动记录、复盘文档和研究资料。页面可借用只读投影，不能取得聚合可变引用；所有修改经 `dispatch(Command)`，分组唯一性、阈值、预案完整性及记录身份由核心统一约束。命令先在候选副本上验证，通过后整体替换，失败不改变记录或 ID 分配进度。这条路径服务于有大小上限的人工业务文档，不用于逐笔行情。读取业务数据可跨页共享；InputState、FocusHandle、输入订阅和阅读窗口布局仍由各个视图独立创建。盯盘分组与行情股票列表使用不同身份和成员集合，不按同名自动同步。暂停监控阻止手动生成演示异动；切页本身不改变监控状态，也没有启动后台行情轮询。

`DesktopEvent` 表达个股速览、打开行情、加入盯盘、创建草稿、进入题材和提示。`SourceContext` 携带来源页面、资料日期、板块、股票与依据。加入盯盘先选目标分组、展示去重结果，确认后仅追加缺少成员；引用复盘先确认目标业务日，每次新建独立草稿。资料源日期与复盘业务日分别保留，经速览再次引用也不丢失来源。打开行情复用已有面板的选股/联动逻辑，不用研究页面替换 Dock 树。编辑对话框打开时限制跨页跳转，避免输入上下文被隐式切换。

涨停资料按各日原始板块顺序显示，字段文本查询使用 AND 条件；编辑、样例导入和整日删除作用于该页资料。题材的四板对象、周期、关键词与截止日联动是固定演示证据，涨停资料变更不会触发算法重算。显示请求截止日和实际使用日期不代表已经实现附件 42 的全部查询或旧算法兼容。

复盘按业务日存放 `Plan`、`Draft` 和盘中笔记，每条预案/草稿有稳定 ID。完整预案要求板块及至少一侧方式与触发条件，允许只写卖出侧；任一侧已有内容时必须补齐该侧必要字段，不完整内容保存为草稿。按 ID 编辑不会重复追加，原预案已删除时更新报错。草稿与笔记编辑同步共享文档并防抖写盘，切换日期使用编辑器绑定的日期，不按后来选中的日期误写。人工热点最多 5 条；手工收益先取日期最近的 10 笔再按收益展示，严格大于 10% 才高亮，不代表账户收益核算。

研究资料由核心 `ResearchDocument`/`ResearchRow` 解码与校验，页面持有用于显示和编辑的副本，提交后才更新聚合；不再由视图持有或解释无类型业务 JSON。兼容边界保留旧 `research` 字段及未识别扩展字段；无法解码的研究子文档保留原值，拒绝研究修改，但不阻止保存其他有效业务记录。

核心提供一条可重放的模拟候选链：已核验收盘事实 → 当时题材归属 → 人工确认 → 首板候选 → 交易日历中的下一日草稿。`TradingDate`、`ResearchTime` 和 `ThemeId` 在构造及反序列化时校验；查询只读取截至 `as_of` 可知的事实、归属和人工判断，同股跨题材去重并保留各条依据，板数未知与明确排除分开。未确认的系统建议不会覆盖人工结论。候选保存规则版本、事实来源/版本/可知时刻、归属版本和判断引用，草稿保留 typed `CandidateSet`，不只留下显示文字。

题材页“模拟候选演练”明确使用固定 2026-10-14 样例，用户点击确认示例强势后，建立 2026-10-15 的未完成草稿。它独立于上方可编辑资料，不把固定四板对象当成计算结果；没有实现涨停价格核验、连续四板推导、五组赚钱效应指标或真实题材认定。现有证券目录仍是固定 `Symbol`，日期时刻采用同一市场本地日历；跨市场身份、供应商协议、完整日历服务与行情后台仍需后续任务。

复盘阅读窗口是独立 GPUI 原生窗口，按打开时的业务日期读取共享预案和笔记，输入/焦点独立创建；关闭窗口只结束阅读视图，不删除复盘记录。存在被核心拒绝的输入时，阅读窗口和主窗口各自最多显示一个关闭确认框；重复关闭请求不能叠加确认，继续编辑或 Esc 取消后保留输入并允许再次确认。它不属于行情 Dock 树、看板布局撤销或持久组件身份空间。

## 面板身份与窗口归属

工作区由多个命名看板组成，运行时只挂载活动看板的原生窗口和面板。切换前捕获当前看板的完整布局、内容和浮窗，目标恢复成功后才变更活动身份；失败回滚源看板。未活动看板以快照保存，不能留在 live 面板注册表中，否则股票联动和插入目标会串到其他看板。主窗口的当前位置与尺寸保持不变，各看板的浮窗按其记录重建。

看板 ID 与组件/窗口 ID 分别分配。组件与浮窗分配器扫描所有看板的历史 ID 并单调前进，复制看板会重新分配组件和非主窗口 ID，同时保留内容。看板内主窗口 ID 始终为 `0`。看板名称去除首尾空白后应唯一、非空、不含控制字符，最多 24 个字符，支持最多 16 个看板且不能删除最后一个。

`PanelModel.id` 是持久身份，GPUI `EntityId` 是运行时身份，两者不可替代。复制面板分配新的持久 ID；移动面板保留原 ID、股票、周期、表单与图表视口。主窗口 ID 为 `0`。

`PanelModel.custom_name` 是可选显示名，缺省为组件类型名称。组件标签、独立窗口标题及插入目标使用同一有效标题；组件类型和持久 ID 不因改名改变。名称去除首尾空白，空值恢复默认，最多 32 个字符且不含控制字符。旧模型缺字段时仍可读取，复制和移动保留名字，布局撤销保留存活组件的当前名字。

`PanelContent` 按 `PanelKind` 构造 `PanelView`：股票列表只拥有搜索/导入输入，图表只拥有图表实体，模拟委托与委托明细分别拥有所需字段，只读面板不创建无关输入或图表。`panels::snapshot` 保留旧内容字段及缺省值，包括当前类型未使用的旧字段，避免保存时丢弃历史内容。恢复先完整解码校验，再修改 live 控件；坏的已知内容显式失败，不能被当成“没有保存内容”。缺失/null 的旧内容仍按原有缺省规则创建。

每个持久面板在一次完成的操作后只能属于一个窗口。跨窗口迁移先在目标窗口重建内容、输入、焦点与订阅，成功后移除源面板；失败必须撤销目标并恢复源注册。不能把绑定原窗口的 InputState 或 FocusHandle 直接挂到另一窗口。旧实体移除时不得清除已经由新实体接管的同一持久 ID。

新增和复制组件先创建独立原生窗口，再装载内容并激活焦点；创建失败要回收空窗口。新组件继承来源窗口的联动股票，复制组件则保留其快照并分配新 ID。组件类型决定初始窗口大小，窄数据组件允许缩小到 240 像素宽。

普通标签拖拽由 DockArea 处理窗口内布局，组件内部股票标题和跨窗拖柄由 DragCoordinator 处理窗口间移动。“插入面板”菜单直接选择目标面板与方向，调用同一迁移路径。源/目标锁定、失效目标或错误窗口归属必须在修改前拒绝。

拖动单组件浮窗时，命中检测跳过源窗口以便找到后面的工作区；只对持久组件总数为一的源浮窗生效，非活动标签也参与计数，不能把多标签窗口当作单组件窗口透传。原生系统标题栏仍用于移动整个窗口。

用户关闭浮动窗口会删除其中全部组件，包括未选中标签；关闭不等于返回主窗口，也不受布局锁定阻止。删除前捕获最新内容用于布局撤销，移除窗口和组件注册、取消相关拖动并保存当前看板。原生关闭回调必须校验窗口运行时身份，避免延迟事件删除已恢复的新窗口。程序性窗口回收（迁移、切换看板、恢复）保持独立路径，不解释为用户删除。主窗口关闭时先保存全部看板再退出，保留未关闭的浮窗。回归应分别验证显式删除、可撤销恢复和迁移状态连续。

屏幕命中统一在设备像素坐标中计算，再按目标显示器转换窗口位置。Windows 使用显示器 DPI，混合 DPI 必须在 Windows 实机验收。保留的跨平台实现中，Linux X11 使用桌面坐标；Wayland 不提供所需全局坐标，禁用自由跨窗拖柄，使用插入菜单、弹出/返回和窗口内停靠。这些 Linux 行为待恢复跨平台工作后重新验证，不构成当前交付要求。

## 数据与业务状态

新默认面板选中 `Yinli`，旧面板沿用序列化股票；`Symbol::ALL` 包含 18 只样例，其中 12 只 A 股、4 只美股、2 只港股；`LEGACY_DEFAULTS` 保留原六只供旧快照缺省恢复。新建行情列表使用当前全部目录，不向已有列表自动追加；扩充目录不改写旧股票枚举的序列化名称。

图表通过 `adapters::market_data::ChartSource` 查询 `ChartDataProvider` 的投影，绘制层不直接选择模拟数据生成器。投影包含可见 Bar、均线所需前缀、参考价、时轴、交易阶段和竞价参考；历史投影保留固定时点。现有接口同步读取已可用数据，不能放入网络等待；真实数据适配应先异步更新缓存，再由投影提供一致快照。当前只是图表查询边界，其他报价面板及模拟账户并未因此变为真实后端客户端。

Session 管理统一行情 tick；各面板对同一股票和 tick 应得到一致数据。联动组 `0` 表示独立，`1` 至 `3` 的同组面板同步选股。图表周期和视口属于具体实例，不应因新开另一个图表而被覆盖。

`Watchlist` 保留序列化名称，显示为“股票列表”。每个组件的内容快照分别保存 `members` 股票成员、搜索与排序；一个组件对应一个独立分组，不使用全局自选集合。缺少 `members` 的旧快照默认采用原有六只示例股票，显式空数组必须保留为空。添加去重、移除只修改当前成员，不能因外部选股联动改变成员，也不能因移除行事件冒泡触发选股。名称和成员属于内容配置，不产生布局撤销步骤；复制内容后各组件独立修改。

文本导入仅匹配当前 `Symbol` 目录，不生成未知证券或请求网络数据。解析按完整代码/名称匹配并保持首次出现顺序，确认时依据当前输入和成员重新计算，只追加缺少的股票并发出 `ListChanged`，不改变选股、搜索、排序或其他分组。预览、草稿和读取状态属于窗口内临时 UI，不进入 `ContentSnapshot`，旧布局格式不变。跨窗重建、切看板或返回列表会丢弃未确认草稿。

文本文件通过系统选择器读取，后台执行有界磁盘读取和解码，使用已有锁定版本的 `encoding_rs` 支持 UTF-8、带 BOM 的 UTF-16 与 GB18030。原始字节和解码后文本均限 256 KiB，最多 5000 条候选，超限整批报错。异步回写校验源内容弱引用、请求编号及文本编辑版本；取消、清空、改稿或迁移后的迟到结果不能覆盖新输入。解析及预览本身不会修改成员。

`Trades` 保留原有序列化名称，显示为“成交明细”；新增 `TradeDetails`（逐笔成交）和 `OrderDetails`（市场委托明细），与模拟账户的 `Orders` 区分。逐笔数量与金额汇总回成交明细，未撤销的市场委托汇总回十档盘口。市场委托只是展示用数据，不是用户的模拟账户委托。

新增月 K、1 分和 5 分 K 线保留原有周期名称。价格/成交量均线基于完整可用历史计算后再裁剪视口；分时均价使用完整模拟交易时段，不能随着可见窗口向后滚动而重新从零累计。所有数据仍是确定性演示，市场日历和估值不代表实时信息。

分时采用股票所属市场的固定全天时轴，忽略旧视口裁剪参数，不支持缩放/平移；K 线保留原视口行为。A 股演示从 10:00 起按墙钟分钟推进，午休不产生样本，15:00 封顶，不取模重启。开/收盘竞价参考价独立于成交 `Bar`；仅撮合点进入 OHLC、量额和均价。主图、量图、时间标签与命中测试共用时间映射；未来、开盘等待和午休间隙不命中成交。美港股保留自己的时段，港股午休同样不产生样本。报价、盘口及逐笔使用最后已成交时刻，休市和收盘后冻结成交快照。

图表定位以样本时间标识保存当前选中项，再映射到可见视口，不把屏幕横坐标或裁剪后的局部索引当作交易日。点击进入定位，拖动阈值把平移与双击查看区分开；切换股票或周期清除定位。定位与数据卡为临时 UI 状态，不改变原有 `ChartViewport` 存储格式。

分时检视是临时开关：首次单击有效成交点开启，移动或方向键更新定位，再次单击画布同时关闭十字线和数据卡；关闭后 hover 不会自行开启。卡片的左右吸附依据固定全天时轴上的真实横坐标，不能用当前已有样本的索引比例。卡片均价取所选分钟的累计序列值，分钟成交量/额取该 Bar 并沿用现有整数分 OHLC 均值口径，不引用当前最新报价。历史分时复用相同交互；历史窗口的键盘事件在冒泡阶段处理，图表检视先消费 Esc，未定位时 Esc 才关闭窗口。

日 K 双击发出 `ChartEvent::InspectDay`，携带股票、完整日线序列索引和当时 tick。`market::historical_session` 返回该日的 OHLC、前收、分钟数据、量额和相邻可用日；已完成日的分钟聚合严格还原同一日 K，当前日复用固定 tick 的模拟会话。均价/成交额采用相同整数分 OHLC 均值加权口径，不能引用另一天的当前报价来填历史字段。

每个 `PanelContent` 仅弱引用一个历史查看窗口，重复打开时更新并激活它。历史窗口创建独立 `MarketChart` 和焦点，冻结行情，不参与联动、布局快照及撤销；源内容释放时延迟关闭，覆盖组件移除、跨窗重建和看板切换。关闭历史窗口不修改源图，关闭主窗口仍执行原有保存退出流程。

DemoBroker 由组成根统一初始化，是当前进程中的共享模拟账户；服务不再依赖某个 PanelContent 首次构造时懒初始化。提交、撤单和模拟成交更新资金/持仓及占用量，不发送真实交易。USD、HKD、CNY 余额各自独立，沪深股票共用 CNY 资金及委托占用；A 股样例并不意味着已实现 T+1、最小交易单位等完整交易规则。账本在重启后重置，订单输入等面板内容随布局保存。将来接入数据或券商时应建立明确的数据接口及异步边界，不能让演示按钮直接调用真实下单接口。

## 布局持久化与撤销

`workspace.json` 使用外层 `BoardSetFile` schema `2`，保存看板顺序、名称、活动 ID 和每个看板的完整 `WorkspaceFile`。单看板快照仍使用 schema `1`，包含窗口边界、Dock 树、锁定状态、面板模型与内容、ID 分配进度及暂停状态，供现有恢复/撤销逻辑复用。旧 schema `1` 文件读取后完整包装为一个“默认看板”，首次保存新格式时将原始文件保留为 `.bak`。布局保存在平台配置目录，可用 `TYDARO_DATA_DIR` 隔离测试；路径和运行方法见 [build.md](build.md)。

存储层先校验再写入，通过临时文件和替换保留旧数据。之前有效版本写入 `.bak`；不可读的旧内容保留为 `.corrupt-*`。当前不自动迁移未知 schema，也不自动加载 `.bak`；遇到不可读布局会显示状态提示并使用默认布局。修改存储逻辑时不得把备份误写为坏文件。

有效性约束包括每个看板最多 16 个窗口、128 个面板、64 层嵌套，整个文件最多 8 MiB，以及合法 ID、有限窗口尺寸和联动组。每个看板必须包含且仅包含一个主窗口，活动看板必须存在。未知面板名称及 JSON payload 在存储层保持原样；这不代表已经支持第三方插件。已知面板的坏数据应显式报错，不能当作未知类型吞掉。新增字段需定义默认值或迁移并覆盖旧数据读取测试。

委托筛选、大单筛选和盘口队列切换随内容快照保存，字段使用 serde 默认值读取旧布局。不得更名旧的 `PanelKind` / `Period` 序列化值来替换显示标题。

自动保存将活动看板的 live 快照与所有未活动看板合并写入，不能仅保存当前窗口。`template.json` 继续使用单看板 schema `1`，保存和加载模板只涉及当前看板。布局撤销历史按看板分别保留在当前会话中，切换本身不成为布局撤销项。行情时钟、暂停状态及 DemoBroker 仍全局共享，切换不倒退演示进度或账户。

Session 最多拥有一个布局后台保存任务：UI 捕获完整 `BoardSetFile`，后台执行验证、编码和磁盘操作。保存过程中出现更新时保留 dirty 与新 revision，旧回调不能清除它，随后保存最新快照。`workspace::flush` 取消未完成回调，与后台任务共用串行写会话，等待已开始的 IO 并提交更高版本；旧请求不能在关闭 flush 之后覆盖新数据。该写会话仍使用原布局 `.bak`/`.corrupt-*` 规则，没有因此获得桌面业务文档的外部修改 baseline 拒写或多进程事务保证。

应用布局前先准备目标窗口，失败尝试回滚原工作区。撤销以布局操作为主：保留仍存活面板的当前股票、周期、表单和视口，不倒退正在变化的业务状态；恢复已关闭面板时使用保存内容。ID 分配不能因撤销而倒退。现有原生窗口恢复尺寸时保留当前位置，因为当前 GPUI 没有窗口位置 setter；新建窗口及重启恢复使用经过可见区域约束的位置。

## 桌面业务持久化

业务使用同一平台配置目录下独立的 **`desktop.json` schema `2`**，由核心文档契约、`src/app/state/` 适配与 `src/adapters/desktop/` IO 共同负责，不复用或迁移 `workspace.json`。保存内容包括活动页面、盯盘分组及成员、监控/静音开关、规则与最多 100 条异动、按日预案/草稿/笔记、人工热点、手法、手工收益及已确认的涨停资料修改。研究筛选、选中、对话框位置和阅读窗口布局为临时视图状态。题材演示证据不因保存涨停资料而被重新计算。

`app::state::dispatch` 仅在命令成功后推进 revision、刷新视图并安排 700 ms 防抖保存。适配器拥有可替换的 Task；捕获文档副本后，在后台执行编码、验证、备份与磁盘替换。所有写入通过同一写会话串行化；旧请求不能覆盖较新的已保存版本，过期完成回调不能把新修改标为已保存。主窗口关闭时调用 `save_now`，取消防抖、等待已开始的写入并同步提交最新版本；关闭是明确的持久化边界，并非声称所有 IO 都不等待。桌面业务保存失败会阻止直接关闭，并显示“继续编辑 / 仍然退出”选择；继续编辑保留内存，只有显式选择仍然退出才丢弃未保存的业务修改。测试模式 `persistent = false` 不读取或写入用户配置目录。新文件不存在时使用演示初值；现有行情看板和股票列表不会被新业务默认分组替换。

schema `1` 文档先按旧格式校验，再经 `Desktop::try_from` 显式转为 schema `2`；旧预案没有 `research_evidence` 时保持 `None`，原 ID、业务日及 source 文字原样保留，不能从文字猜测新证据。首次成功保存写入 schema `2`，有效旧文件原字节进入 `.bak`。旧版应用会拒绝未知 schema `2`，避免读后丢弃证据字段。未来版本拒绝读取和覆盖；`workspace.json` 的看板 schema `2`、内层工作区 schema `1` 以及 Gallery schema `1` 均不改变。

读写均限制为 8 MiB，并检查版本、记录身份与分配进度、日期、数量、股票重复、文本长度和有限数值。保存前先校验新文档，写入同目录独占临时文件并同步，再原子替换；上一个有效文件原字节保留在 `desktop.json.bak`。Windows 替换前释放临时文件句柄。只有写入成功才显示“已保存到本机”。

桌面业务与旧布局的失败保护策略有意分开：**读取到损坏、未知版本或无法读取的 `desktop.json` 时保留原文件并禁止覆盖**，界面使用演示初值，后续修改仅留当前进程内存。保存时若检测到文件已被外部修改或删除，同样停止覆盖。不会自动从 `.bak` 恢复，也不会把损坏原文另存后继续覆盖；恢复文件后需重新打开应用。研究资料子文档解析失败时保留其原 JSON，该页暂停修改。

写入失败保留内存修改并显示错误，不能把它当作已持久保存；显式选择仍然退出、强制终止或崩溃后未落盘内容可能丢失。该文件是本地前端业务文档，不是 SQLite、旧数据库迁移、跨设备同步或多进程事务服务。布局撤销仅作用于行情布局，不撤销研究编辑或复盘业务记录。

## 演进原则

优先保持上述边界与可验证行为；模块拆分应由实际复杂度推动，不预先引入通用插件系统或多服务架构。跨模块协议、布局 schema、工具链或发行方式变化时，在相应文档/PR 记录原因、兼容方案和验证证据，避免把关键决策只留在对话中。
